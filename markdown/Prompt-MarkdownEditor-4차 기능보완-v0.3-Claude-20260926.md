## 0. 한눈에 보기

- **할 일**: 이미 동작하는 단일 문서 MarkdownEditor(PySide6 + QtWebEngine)에 ① 편집기 글간격 조절, ② 문서 탭, ③ Explorer 파일 끌어다 놓기 열기를 추가한다. 처음부터 다시 만들지 않고, 필요한 부분만 안전하게 리팩터링한다.
- **핵심 위험(실측, §4)**: 문서 상태가 `MainWindow` 한 곳에 있다. 편집 메뉴·찾기 창·자동 줄바꿈이 첫 편집기에 직접 묶여 있다. 미리보기마다 외부 이미지 차단기를 공유 WebEngine 프로필에 새로 설치하고, 닫을 때 프로필에서 제거한다. 탭을 단순 복제하면 "다른 탭이 편집됨", "탭 하나를 닫으면 모든 탭의 외부 이미지 차단이 풀림" 같은 회귀가 생긴다.
- **끌어다 놓기가 지금 안 되는 이유(실측)**: 편집기에 파일을 놓으면 `QPlainTextEdit` 기본 동작으로 `file:///…` 글자가 본문에 삽입된다. 기존 GUI 테스트는 `MainWindow.dropEvent()`를 직접 호출해서 실제 자식 위젯 경로를 검증하지 못했다.
- **검증은 정직하게**: 실행하지 못한 검사는 `NOT_CHECKED`로 쓰고 사유를 남긴다. 합성 Qt 이벤트로 확인한 것을 실제 Explorer 끌어다 놓기로 확인했다고 보고하지 않는다.
- **시작점**: §13의 M0(실사·결정 확인). 각 마일스톤은 실행 증거로 완료를 판단한다.

## 2. 요구사항

### 2.1 PRD 원문

> **왼쪽 에디팅 창 편집 모드 설정** — 글자 글간격 설정 기능: Top 메뉴의 보기 메뉴에 `글간격 크게`, `글간격 작게` 추가. `글간격 크게` 하면 에디팅 창의 글자의 글자 간격을 1단계씩 크게 한다. `글간격 작게` 하면 에디팅 창의 글자의 글자 간격을 1단계씩 작게 한다.
>
> **문서 Tab 기능 추가** — 문제점: 1개의 마크다운만 편집이 가능해서 여러 마크다운을 편집할 때 불편하다. 문서 Tab을 상단에 추가하여 여러 파일을 편집할 수 있게 한다. 문서 Tab별로 1개의 마크다운 파일을 편집하고 볼 수 있다.
>
> **마우스 Drag & Drop으로 파일 열기** — 마우스의 Drag & Drop 기능으로 Explorer에 있는 마크다운 파일을 열 수 있다. Explorer에 있는 마크다운 파일을 에디팅 창이나 Viewer 창에 Drag & Drop 하면 파일을 열 수 있다.

## 3. 작업 원칙, 사용자 확인, 금지 사항

### 3.1 작업 원칙

너는 AI, Python, Markdown·HTML 문서 포맷, Windows 자동화, PySide6·QtWebEngine, 데스크톱 GUI에 능숙한 시니어 개발자다. 설명·설계안·의사 코드에서 멈추지 말고 실제 코드를 고치고, 의미 있는 자동 테스트를 추가하고, 실사용 샘플 검증, 한국어 문서, Windows 배포 산출물까지 현재 코드와 일치하게 갱신한다.

1. 기존 구현을 폐기하지 말고 현재 구조를 조사한 뒤 필요한 부분만 리팩터링한다. 앱 규모에 비해 과한 프레임워크나 새 외부 의존성을 들이지 않는다.
2. 구현 중 오류가 나면 원인을 조사해 고치고 관련 검사와 회귀 검사를 다시 실행한다. 한 번 실패했다고 계획만 남기고 멈추지 않는다.
3. 권한 승인, GUI 세션 부재, 필요한 외부 자산 부재처럼 직접 해결할 수 없는 조건만 차단 사유로 인정한다. 차단되지 않은 항목은 계속한다.
4. 코드 식별자는 영어로, 사용자 UI·문서·오류 메시지·최종 보고는 자연스러운 한국어로 쓴다. 새 UI 문자열은 `ui_text.py`에 모은다.
5. 모르는 사실은 추측하지 말고 모른다고 기록한다.

### 3.3 금지 사항

- `markdown\`의 PRD·프롬프트, `samples\` 원본을 수정·삭제·이동하기. `samples\`에 저장 테스트 파일을 만들기. 이미 있는 날짜 붙은 사본(`…_20260919.md`, `…_20260920.md`)도 지우지 않는다.
- 사용자가 이미 바꾼 파일이나 이번 작업과 무관한 변경을 되돌리거나 덮어쓰기.
- 기존 테스트를 삭제하거나 assertion을 약하게 바꿔 통과시키기. 0개 수집된 테스트 실행을 성공으로 보고하기.
- 실행하지 않은 검사를 `PASS`로 쓰기. 캡처를 열어 보지 않고 화면 검사를 `PASS`로 쓰기. 합성 Qt 이벤트 결과를 실제 Explorer 끌어다 놓기 결과로 보고하기.
- 파일 끌어다 놓기를 `acceptProposedAction()`으로 받기(§7.3).
- 탭 하나를 닫을 때 공유 WebEngine 프로필 설정(요청 가로채기 등)을 바꾸기(§6.8).
- 탭마다 단축키가 있는 `QAction`을 새로 만들기(§6.3).
- 탭 관련 코드를 모두 `main_window.py`에 넣어 거대한 조건문으로 만들기.

## 5. R4-01 편집기 글간격

### 5.1 메뉴와 동작

- `보기(V)` 메뉴의 `글자 크게`·`글자 작게` 바로 아래에 `글간격 크게`, `글간격 작게`를 추가한다.
- 한 번 누를 때마다 5%p씩 바꾸고 80~150% 안에서만 움직인다. 경계에 닿으면 해당 액션을 비활성화한다(상태 표시줄의 글자 크기 `-`/`+` 버튼과 같은 방식).
- 바꾼 값은 열려 있는 **모든 탭의 편집기**와 이후 새로 여는 탭에 똑같이 적용한다. 미리보기의 자간은 바꾸지 않는다.
- 바꿀 때마다 상태 표시줄에 `편집기 글간격 105%`처럼 알린다. **[권장]** 글자 크기 표시 옆에 현재 글간격을 계속 보이는 표시를 둔다.
- **[선택]** `글간격 기본값`(100%) 액션과 단축키. 단축키를 추가하면 기존 단축키와 겹치지 않아야 한다(§8.2의 중복 검사).

### 5.2 설정 저장

- `QSettings` 키 `view/letter_spacing`에 정수 백분율로 저장하고 다음 실행 때 복원한다.
- 값이 없거나 숫자가 아니면 100%로, 범위를 벗어나면 가까운 경계값으로 복원한다. 잘못된 값 때문에 앱이 시작하지 못하면 안 된다.

### 5.3 구현 기준

- 편집기 글꼴은 (글꼴 이름, 크기, 글간격)을 받아 만드는 함수 하나(예: `gui/fonts.py`의 `editor_font(size, spacing)`)에서만 만든다. 글자 크기 변경, 글간격 변경, 새 탭 생성 모두 이 함수를 쓴다. 지금의 `set_markdown_font_size()`처럼 글꼴을 새로 만들면서 글간격을 지우지 않게 고친다.
- 다음 단계 계산, 범위 제한, 설정값 해석은 Qt 없이 테스트할 수 있는 순수 함수로 만든다.
- **(실측)** PySide6 6.11.2에서 맑은 고딕 12pt `가나다라마바사`의 폭이 100%에서 112px, 120%에서 134px로 늘었고, 이후 `setStyleSheet()`를 호출해도 글간격이 유지되었다. 앱의 다크 모드 전환(`set_dark_mode()`가 스타일시트를 다시 적용)에서도 유지되는지 테스트한다.
- 줄 번호: **[권장]** 줄 번호 영역은 글간격 100% 글꼴로 그리고 폭도 그 글꼴로 계산한다. **[필수]** 150%에서 4자리 줄 번호(제안요청서 샘플 4,720줄)가 잘리거나 본문과 겹치지 않는다.
- 커서·선택 범위, 실행 취소 기록, 수정 표시, 한글 IME 입력, 구문 강조, Sync Scroll 줄 계산에 부작용이 없어야 한다. 글간격 변경은 문서 수정으로 취급하지 않는다.

## 6. R4-02 문서 탭

### 6.1 화면 구성

```text
메뉴: 파일(F)  편집(E)  서식(O)  보기(V)  도움말(H)
탭:   [설문지_기업 인공지능 활용 실태조사.md ×] [차세대무역플랫폼 … 제안요청서.md * ×]
+--------------------------------+--------------------------------+
| 마크다운 툴바 (탭마다, 액션 공유) | Sync Scroll · 위치맞춤 (탭마다)  |
|--------------------------------|--------------------------------|
| 편집기 (줄 번호)                 | 미리보기 (QtWebEngine)          |
+--------------------------------+--------------------------------+
연결 문제 패널 (아래 도킹, 활성 탭 기준)
상태 표시줄: 경로 | 인코딩·줄바꿈 | 줄·칸 | 연결 | 렌더 | 글자 - 12 + | 간격 100%
```

- `QTabWidget`(또는 `QTabBar` + `QStackedWidget`)을 쓴다. 탭마다 닫기 버튼을 두고, 끌어서 순서를 바꿀 수 있게 하며, 탭이 하나여도 탭 표시줄을 보인다.
- 탭 제목은 파일 이름이고, 수정되면 ` *`를 붙인다. 툴팁에 전체 경로를 보인다. 긴 이름은 가운데를 줄여 표시한다. **[권장]** 같은 이름의 파일이 여러 탭에 열리면 상위 폴더 이름을 덧붙여 구분한다.
- 창 제목은 `MarkdownEditor - <활성 파일 이름>`이고, 활성 문서가 수정되었으면 ` *`를 붙인다.
- 문서가 하나도 없으면 탭 대신 안내 화면을 보인다: 기존 `NO_DOCUMENT` 문구("마크다운 파일을 열거나 창으로 끌어다 놓으세요."), `열기` 버튼, **[권장]** 최근 파일. 안내 화면도 끌어다 놓기를 받는다. 이때 문서 관련 액션은 비활성화한다.
- 마지막 탭을 닫아도 앱은 끝나지 않고 안내 화면으로 돌아간다. 빈 새 문서를 자동으로 만들지 않는다.

### 6.2 문서 세션과 상태 소유

탭 하나의 문서 상태를 모두 가지는 단위(예: `DocumentSession`, `QObject` 하위 클래스 권장)를 만든다. 이름과 파일 위치는 코드에 맞게 정하되 소유 관계는 아래 표를 따른다.

| 상태 | 소유 | 비고 |
|---|---|---|
| `LoadedDocument`, 경로, 인코딩·BOM·줄바꿈 정보 | 세션 | |
| 편집기 위젯(글, 실행 취소 기록, 수정 여부, 커서·선택, 스크롤 위치) | 세션 | |
| 미리보기(`PreviewPane`, 문서 기준 폴더, DOM, 스크롤 위치) | 세션 | 생성 시점은 §6.8 |
| 탭 페이지의 splitter, 툴바 위젯, 미리보기 제어 줄 | 세션 | 툴바 액션 자체는 전역 |
| 렌더 타이머·revision·마지막 결과·오류, 연결 요소 점검 결과 | 세션 | |
| Sync Scroll 타이머와 되먹임 방지 플래그 | 세션 | 켜짐 여부는 전역 |
| 메뉴, `QAction`, 단축키 | 전역(`MainWindow`) | 호출 시점의 활성 세션에 적용 |
| 다크 모드, 글자 크기, 글간격, 자동 들여쓰기, 자동 줄바꿈, 외부 이미지 표시, Sync Scroll 켜짐, 보기 모드 | 전역 | 모든 탭과 새 탭에 적용 |
| 최근 파일, 창 위치, 연결 문제 패널, 상태 표시줄, 찾기 창 | 전역 | 활성 세션의 내용을 보인다 |
| 외부 이미지 차단기(`NetworkGuard`), 렌더 스레드 풀 | 앱 전체에 하나 | §6.8 |
| 이번 실행에서 저장한 경로(`session_saved_paths`) | 전역 | 날짜 저장 규칙(§6.6) |

- `MainWindow`는 메뉴·액션, 전역 설정, 최근 파일, 탭 관리, 종료 조정만 맡는다.
- 기존 테스트와 검증기를 위해 `window.editor`, `window.preview`, `window.document_data` 같은 이름은 활성 세션의 값을 돌려주는 읽기 전용 속성으로 남길 수 있다(문서가 없으면 `None`). 상태를 다시 `MainWindow` 필드에 저장하지 않는다. 테스트가 쓰는 비공개 속성(`preview_sync_timer`, `_pending_preview_source_line`, `_choose_save_target`)은 세션으로 옮기고, 테스트는 같은 의미를 검사하도록 고친다.
- 세션은 탭 인덱스가 아니라 탭 페이지 위젯(또는 세션 객체)으로 찾는다. 탭 순서를 바꾼 뒤에도 저장·닫기가 맞는 문서에 적용되어야 한다.

### 6.3 액션 라우팅

- 편집 메뉴 전체, 서식 메뉴·툴바 명령, 찾기·바꾸기·다음 찾기·줄로 이동, 미리보기 새로 고침, `Sync Scroll 위치맞춤`, 파일 위치 열기, 저장·다른 이름으로 저장은 **실행되는 순간의 활성 세션**에 적용한다. 생성 시점의 위젯 메서드에 직접 연결하지 않는다(§4의 편집 메뉴·자동 줄바꿈 연결을 고친다).
- 툴바 액션은 `MainWindow`(또는 별도 액션 모음)에서 한 번만 만든다. 탭마다 만드는 툴바 위젯에는 그 액션 객체를 추가해서 쓴다. 제목 수준 콤보 상자 같은 위젯 항목은 탭마다 만들되 같은 명령 신호로 연결한다. 기존 GUI 테스트의 "단축키 중복 없음" 검사가 계속 통과해야 한다.
- 툴바 하나를 활성 탭 페이지로 옮겨 붙이는 방식도 허용한다. 이때도 툴바가 편집기 바로 위에 있고, 미리보기 제어 줄 높이를 툴바 높이에 맞추는 현재 배치(`set_control_height`)를 유지한다.
- 찾기·바꾸기 창은 탭을 바꾸면 대상을 활성 탭 편집기로 바꾸거나 닫는다. 다른 탭 편집기에 바꾸기가 적용되면 안 된다.
- 새 액션 `탭 닫기`에는 `QKeySequence.StandardKey.Close`를 쓴다. Windows에서는 `Ctrl+W`, `Ctrl+F4`이며 앱에 이미 있는 단축키와 겹치지 않는다(실측, `끝내기`의 표준 단축키는 Windows에서 비어 있다).
- 탭 전환: `QTabWidget` 기본 `Ctrl+Tab`/`Ctrl+Shift+Tab` 전환이 편집기 포커스와 WebEngine 포커스 모두에서 합성 키 입력으로 동작했다(실측). 실제 앱 구조(splitter, 사용자 정의 `keyPressEvent`)에서 다시 확인한다. 안 되면 `StandardKey.NextChild`/`PreviousChild` 액션으로 보완하되, 두 방식이 겹쳐 한 번에 두 칸씩 넘어가지 않게 한다.
- **[선택]** `다른 탭 닫기`, `모든 탭 닫기`.

### 6.4 파일 열기 공통 경로

- 모든 열기 입구를 공통 함수 하나(예: `open_paths(paths, origin) -> OpenSummary`)로 모은다: `파일 > 열기`(여러 개 선택, `getOpenFileNames`), 최근 파일, 명령줄(여러 파일), 미리보기의 `.md` 링크, `도움말 > 사용 설명서`, 끌어다 놓기(§7).
- 처리 순서: 경로 정규화 → 중복 확인(이미 열려 있으면 그 탭을 활성화하고 다시 읽지 않는다) → `load_document()` 검증(기존 인코딩·확장자·크기 규칙 그대로) → 새 탭 추가 → 최근 파일 갱신 → 렌더.
- 중복 판정 키: `os.path.normcase(os.path.realpath(path))`로 대소문자, `/`와 `\`, `..`, 상대 경로 차이를 없앤다. **[권장]** 키가 달라도 `os.path.samefile()`이 참이면 같은 파일로 본다(하드 링크, 8.3 짧은 이름 등). 심볼릭 링크와 짧은 이름의 실제 동작은 테스트해서 결과를 `docs\DECISIONS.md`에 적는다.
- 확장자·큰 파일 확인: 메뉴·명령줄·링크로 열 때는 지금처럼 파일마다 확인 대화상자를 띄운다. 끌어다 놓기는 마크다운 확장자만 받는다(§7.2).
- 여러 파일은 요청 순서대로 열고, 마지막으로 성공한 파일(또는 마지막으로 활성화한 기존 탭)을 활성화한다. 하나가 실패해도 나머지 파일과 기존 탭은 그대로 둔다. 결과는 상태 표시줄에 `열림 2 · 이미 열림 1 · 실패 1`처럼 요약한다. 실패가 있으면 실패 목록과 이유를 대화상자 **한 번**으로 보인다(파일마다 띄우지 않는다).
- 파일을 열 때 다른 탭의 저장 여부를 묻지 않는다.

### 6.5 탭 전환과 전역 설정

- 탭을 바꾸면 창 제목, 상태 표시줄(경로, 인코딩·줄바꿈, 줄·칸, 연결, 렌더 시간), 연결 문제 패널, 액션 활성 상태가 활성 문서를 정확히 보여야 한다.
- 탭마다 커서, 선택 범위, 실행 취소 기록, 편집기·미리보기 스크롤 위치, 수정 여부가 전환 뒤에도 그대로 남는다.
- 전역 설정을 바꾸면 모든 탭에 적용한다: 다크 모드, 글자 크기(편집기 글꼴 + 미리보기 배율), 글간격(편집기만), 자동 들여쓰기, 자동 줄바꿈, 외부 이미지 표시, Sync Scroll 켜짐, 보기 모드(편집+미리보기·편집만·미리보기만). 새로 여는 탭도 현재 설정으로 시작한다.
- 다크 모드와 외부 이미지 표시는 미리보기 셸을 다시 불러오므로 탭이 많으면 비용이 크다. **[권장]** 비활성 탭은 다음에 활성화될 때 반영해도 되지만, 화면에 보이는 순간에는 반드시 최신 설정이어야 한다.
- `Sync Scroll` 체크 상자는 탭마다 있지만 값은 하나다. 한 탭에서 바꾸면 다른 탭의 체크 상자를 신호를 막은 상태로 맞춘다(되먹임 금지).
- 양방향 스크롤 동기화와 `Sync Scroll 위치맞춤`은 각 탭 안에서만 동작하고, 비활성 탭의 스크롤 이벤트가 다른 탭에 영향을 주지 않는다.
- splitter: 새 탭은 활성 탭의 현재 비율(없으면 저장된 `window/splitter`)을 쓰고, 종료할 때 활성 탭의 비율을 저장한다. **[선택]** 한 탭에서 바꾼 비율을 모든 탭에 맞춘다. **[선택]** 자동 줄바꿈과 보기 모드도 `QSettings`에 저장한다.
- 비동기 렌더 결과는 그 세션이 살아 있고 revision이 최신일 때만 그 세션의 미리보기에 반영한다. 닫힌 탭이나 다른 탭에 늦은 결과를 적용하지 않는다.

### 6.6 저장

- `Ctrl+S`(날짜 붙여 새 파일), 다른 이름으로 저장, 파일 위치 열기는 활성 탭에만 적용한다. 한 탭을 저장해도 다른 탭의 수정 표시와 원본 정보는 바뀌지 않는다.
- 기존 규칙을 그대로 지킨다: 인코딩·BOM·줄바꿈·끝 줄바꿈 보존, 원본 불변, 같은 날 반복 저장, 대상이 있을 때 [덮어쓰기] [번호 붙여 저장] [취소], 다른 폴더에 저장할 때 상대 링크 경고, 저장 후 미리보기 기준 폴더 갱신.
- **탭 사이 경로 충돌**: 날짜 저장의 대상 경로(번호 붙인 대안 포함)나 다른 이름으로 저장의 경로가 **다른 탭에 열려 있는 파일**이면 덮어쓰지 않는다. 날짜 저장에서는 "다른 탭에서 열려 있는 파일입니다"를 알리고 [번호 붙여 저장] [취소]만 제공한다. 다른 이름으로 저장에서는 충돌을 알리고 저장을 취소한 뒤 그 탭을 활성화한다. v0.2는 다른 이름으로 저장만 다뤘다.
- 저장한 뒤 탭 제목·툴팁, 창 제목, 중복 판정 키, 최근 파일을 갱신한다. 두 탭이 같은 경로를 가리키는 상태가 생기면 안 된다.

### 6.7 탭 닫기와 앱 종료

- 탭 닫기 버튼과 `탭 닫기`(Ctrl+W)로 닫는다. **[선택]** 탭 가운데 버튼 클릭으로 닫기.
- 수정되지 않은 탭은 바로 닫는다. 수정된 탭은 그 탭을 활성화한 뒤 파일 이름이 들어간 [저장] [저장 안 함] [취소] 대화상자를 보인다. [저장]은 §6.6의 날짜 저장 규칙을 따른다. [취소]를 누르거나 저장을 취소·실패하면 탭을 닫지 않는다.
- 앱을 끝낼 때는 수정된 탭마다 차례로 같은 대화상자를 보인다. 어느 단계에서든 취소하면 종료를 멈추고 남은 탭을 모두 유지한다(이미 저장한 탭은 저장된 상태로 남는다). **[선택]** 수정된 문서 목록을 한 번에 보여 주는 대화상자.
- 탭을 닫는 순서: 세션 타이머 정지 → 세션을 닫힘 상태로 표시 → 미리보기 채널·신호 해제 → `PreviewPane.shutdown()`(공유 프로필 설정은 건드리지 않는다) → 탭 제거 → `deleteLater()`. 아직 끝나지 않은 렌더 작업의 결과는 버린다.
- 앱을 끝낼 때는 모든 세션을 정리하고 렌더 스레드를 기다린 뒤(현재 5초) 설정을 저장한다. `app.py`의 종료 경로도 활성 탭 하나가 아니라 모든 세션을 정리하고, 탭이 0개여도 오류가 없어야 한다.
- 탭을 빠르게 열고 닫고 전환해도 `RuntimeError: Internal C++ object already deleted`나 종료 시 충돌이 없어야 한다.

### 6.8 WebEngine 자원과 보안

- **외부 이미지 차단기**: `NetworkGuard`를 앱 전체에 하나만 만들어 공유 프로필에 한 번 설치한다. `외부 이미지 표시` 설정은 이 하나의 값을 바꾼다. `PreviewPane.shutdown()`은 프로필의 요청 가로채기를 해제하지 않는다. 테스트: 탭 A·B를 연 뒤 B를 닫아도 A에서 외부 이미지 요청이 계속 차단된다.
- 미리보기 페이지 설정(`LocalContentCanAccessRemoteUrls=False`, `JavascriptCanOpenWindows=False`, `JavascriptCanAccessClipboard=False`)과 CSP를 탭마다 그대로 적용한다. 새로 `NavigateOnDropEnabled=False`를 추가한다(§7.1).
- **늦은 콜백**: `QTimer.singleShot`에 수신 객체를 넘기거나 `_shut_down`을 확인해, 닫힌 미리보기에서 `runJavaScript`가 호출되지 않게 한다. `runJavaScript` 콜백도 세션이 살아 있는지 확인한다.
- **렌더 작업**: `RenderTask` 결과는 세션 객체의 슬롯으로 받거나(수신 객체가 없어지면 연결이 끊어진다) 세션 ID와 revision을 확인한다. lambda가 반복 변수를 늦게 묶는 문제와 닫힌 탭을 붙잡는 문제에 주의한다.
- **[권장] 지연 생성**: 파일 여러 개를 한 번에 열 때(예: 10개를 끌어다 놓기) 모든 탭의 WebEngine 셸(3.6MB mermaid 포함)을 동시에 만들고 렌더하지 않는다. 비활성 탭의 미리보기는 처음 활성화될 때 만들거나 렌더한다. 활성화되면 최신 글과 설정으로 보여야 한다.
- 탭 수를 임의로 제한하지 않는다. 탭 1·2·4개에서 앱과 `QtWebEngineProcess`의 메모리(예: PowerShell `Get-Process`)와 열기 시간을 재서 기록한다. 재지 못했으면 알려진 제한으로 적는다.

## 7. R4-03 끌어다 놓기로 파일 열기

### 7.1 대상 영역과 구현 경로

| 대상 | 현재 상태 (실측) | 구현 |
|---|---|---|
| 편집기 | `QPlainTextEdit` 기본 동작으로 파일 URL을 글자로 삽입한다 | 편집기(viewport 포함)의 drag·drop을 가로챈다. 로컬 파일 URL이 하나라도 있으면 파일 열기로 처리하고 글자를 넣지 않는다. 로컬 파일이 없으면(편집기 안에서 글 옮기기, 다른 앱의 글, 웹 링크 글) 기존 기본 동작을 유지한다 |
| 미리보기 | 끌어다 놓기 이벤트는 WebEngine 내부 렌더 위젯(`view.focusProxy()`, `QWidget`, `acceptDrops()=True`)이 받는다. 합성 이벤트로는 셸 페이지가 바뀌지 않았지만 실제 Explorer에서의 동작은 확인하지 않았다 | 페이지 설정 `QWebEngineSettings.WebAttribute.NavigateOnDropEnabled=False`(6.11.2에 있음, 실측) + `focusProxy()`에 이벤트 필터(DragEnter·DragMove·Drop)를 설치해 공통 처리로 보낸다. 렌더 위젯이 다시 만들어질 수 있으므로(확인 필요) 바뀌면 필터를 다시 설치한다(예: 뷰의 `ChildAdded` 감시). 안전망으로 셸 이외의 메인 프레임 이동을 `acceptNavigationRequest`에서 막되, `setHtml()`에 의한 셸 로드는 허용한다 |
| 탭 표시줄, 탭 페이지, 툴바, 미리보기 제어 줄, 상태 표시줄 | 일부는 `MainWindow.dropEvent()`가 받는다 | 공통 처리 |
| 안내 화면(문서 없음) | — | 공통 처리 |

- 공통 처리기 하나(예: 이벤트 필터 `FileDropController`)와 Qt 없이 테스트할 수 있는 판정 함수(예: `classify_drop(urls) -> DropPlan`)로 만든다. `MainWindow.dropEvent()` 하나만 고쳐 완료로 보지 않는다.

### 7.2 판정 규칙

| 끌어다 놓은 항목 | 처리 |
|---|---|
| 마크다운 확장자의 로컬 파일 | 새 탭으로 연다. 이미 열려 있으면 그 탭을 활성화한다 |
| 여러 파일 | 전달된 순서대로 처리하고 마지막으로 성공한 파일을 활성화한다 |
| 폴더, 없는 파일, 마크다운이 아닌 파일, 바로 가기(`.lnk`) | 열지 않고 요약에 이유를 적는다 |
| 원격 URL(http·https), 로컬 경로가 없는 가상 파일(메일 첨부 등) | 열지 않는다. 편집기에서는 기본 글 넣기 동작을 유지한다 |
| 한글·공백·괄호·긴 경로 | 지원한다 |

- DragEnter·DragMove 단계에서 열 수 있는 마크다운 파일이 하나라도 있으면 복사 표시로 받는다. 없으면 편집기는 기본 동작을 따르고, 나머지 영역은 받지 않는다(금지 커서).
- 결과는 상태 표시줄에 `열림 N · 이미 열림 N · 건너뜀 N`으로 요약한다. 아무 파일도 열지 못했을 때만 이유 목록이 있는 경고 대화상자를 보인다.
- 끌어다 놓기로 열어도 기존 탭을 바꾸거나 저장 여부를 묻지 않는다.

### 7.3 안전 규칙

- 파일 끌어다 놓기는 항상 `event.setDropAction(Qt.DropAction.CopyAction)` 후 `event.accept()`로 받는다. `acceptProposedAction()`을 쓰지 않는다. Explorer가 이동(Shift 누름, 같은 드라이브 등)을 제안했을 때 이동으로 받으면 원본 파일 처리에 영향을 줄 위험이 있다. 파일은 읽기만 한다.
- 드롭한 파일 경로나 `file:///` 글자가 본문에 들어가면 안 된다(실측: 지금은 들어간다).
- 가로챈 드롭 이벤트는 Chromium에 넘기지 않는다. 미리보기 페이지의 스크립트가 드롭 데이터나 파일 경로를 받지 않게 한다.
- 관리자 권한으로 실행한 앱에는 일반 권한 Explorer에서 끌어다 놓을 수 없다(Windows UIPI). README 문제 해결에 "관리자 권한으로 실행하지 않기"를 적는다. 앱 코드로 이 보안 제한을 우회하지 않는다.
- 실제 Explorer 끌어다 놓기 확인 절차는 §9.3을 따른다.

## 8. 자동 테스트

기존 테스트를 지우거나 assertion을 약하게 바꿔 통과시키지 않는다. 구조를 바꾸느라 fixture나 호출부를 고칠 때도 원래 시나리오의 의미를 유지한다.

### 8.1 단위 테스트 (Qt 창 없음)

1. 글간격: 기본값 100, 5%p 증감, 80·150 경계, 설정값 해석(없음, 문자열, 범위 밖, 소수).
2. 경로 정규화와 중복 키: 대소문자, `/`와 `\`, `..`, 상대 경로. 가능하면 하드 링크에서 `samefile` 판정.
3. 드롭 판정: 로컬 마크다운만 추리기, 입력 순서 보존, 폴더·없는 파일·원격 URL·마크다운이 아닌 파일·`.lnk`·대문자 확장자 분류, 한글·공백·괄호 경로.
4. 명령줄 파서: 파일 0개·1개·여러 개, `--disable-gpu`와 함께 쓰기.
5. 기존 순수 로직 회귀: 파일 입출력, 저장 이름, 렌더링, 편집 명령.

### 8.2 GUI·QtWebEngine 통합 테스트 (`pytest-qt`, 표시 `gui`)

1. `보기 > 글간격 크게/작게`가 모든 탭 편집기의 `QFont` 글간격을 한 단계 바꾸고, 경계에서 액션이 비활성화되며, `QSettings`로 새 창에 복원된다.
2. 글간격이 글자 크기 변경, 다크 모드 전환, 새 탭 생성 뒤에도 유지된다. 150%에서 제안요청서 샘플의 줄 번호 영역 폭이 4자리 숫자보다 넓다.
3. 두 탭을 열면 각 탭의 원문, 미리보기 DOM, 문서 기준 폴더가 맞다. 탭 A를 편집해도 탭 B의 글, 수정 표시, 렌더 결과가 바뀌지 않는다.
4. 탭을 바꿨다 돌아와도 커서, 선택 범위, 실행 취소, 편집기·미리보기 스크롤이 그대로다.
5. 편집 메뉴(실행 취소, 붙여넣기, 모두 선택), 서식 명령, 찾기·바꾸기, 자동 줄바꿈이 활성 탭에만 적용된다(§6.3 회귀 검사).
6. 탭 순서를 바꾼 뒤에도 저장·닫기가 맞는 문서에 적용된다.
7. 느린 렌더 결과가 다른 탭에 적용되지 않는다. 탭을 닫은 뒤 늦게 오는 타이머·렌더·`runJavaScript` 콜백이 오류 없이 무시된다.
8. 같은 파일을 메뉴, 최근 파일, 상대 경로, 대소문자가 다른 경로, 미리보기 링크로 다시 열면 기존 탭이 활성화되고 탭 수가 늘지 않는다.
9. 한 탭을 저장해도 다른 수정 탭의 `*`가 남는다. 날짜 저장 대상이 다른 탭에 열린 파일이면 덮어쓰지 않는다. 다른 이름으로 저장 충돌도 같은 방식으로 막는다.
10. 수정 탭 닫기의 저장·저장 안 함·취소, 그리고 저장을 취소하거나 실패했을 때 탭이 남는지.
11. 수정 탭이 여러 개일 때 앱 종료 중 취소하면 창과 모든 탭이 남는다.
12. 마지막 탭을 닫으면 안내 화면이 나오고 문서 액션이 비활성화된다. 안내 화면에 끌어다 놓으면 파일이 열린다.
13. 외부 이미지 차단: 탭 두 개를 연 뒤 하나를 닫아도 남은 탭에서 외부 이미지 요청이 차단된다.
14. 드롭 이벤트를 **실제 대상 위젯**에 보낸다: 편집기 viewport, 미리보기 `focusProxy()`, 탭 표시줄, 안내 화면. 각각 새 탭이 열리고, 편집기 본문에 URL 글자가 없으며, 미리보기 셸 URL이 바뀌지 않는다. `MainWindow.dropEvent()`를 직접 부르는 방식은 이 항목의 증거로 인정하지 않는다.
15. 여러 파일 드롭(순서, 중복, 무효 항목 섞임). 이동(Move)이 제안된 드롭도 `CopyAction`으로 받는다.
16. 편집기 안에서 글을 끌어 옮기기와 일반 글 드롭은 지금처럼 동작한다(파일 드롭 가로채기의 회귀 검사).
17. 모든 `QAction` 단축키가 겹치지 않는다(기존 검사 유지). `Ctrl+W`로 탭이 닫힌다. `Ctrl+Tab`·`Ctrl+Shift+Tab`이 편집기와 미리보기 포커스에서 탭을 한 칸씩 바꾼다.
18. 기존 GUI 테스트 8개(열기·렌더·편집·저장, Mermaid, 대형 샘플, 보안, 링크, 툴바·단축키, 테마·글자 크기, 들여쓰기)가 계속 통과한다.

### 8.3 테스트 품질

- 테스트마다 임시 INI `QSettings`(현재 fixture 방식)와 임시 폴더를 쓴다. 샘플은 부속 폴더까지 임시 폴더로 복사해 쓴다.
- 테스트 순서에 의존하지 않는다. `QTest.qWait()`를 길게 걸어 우연히 통과시키지 말고 `qtbot.waitSignal`·`waitUntil` 같은 조건 대기를 쓴다.
- WebEngine 결과는 revision과 DOM 상태로 확인한다.
- 0개가 수집되면 실패로 본다. 통과·실패·건너뜀·deselected 수를 나눠 보고한다.
- 합성 이벤트 테스트는 "Qt 이벤트 경로 검증"으로 부르고 실제 Explorer 확인(§9.3)과 구분해 보고한다.

## 9. 실사용 샘플 인수 검증

### 9.1 기준선

- 인수 샘플: `samples\설문지_기업 인공지능 활용 실태조사.md`, `samples\차세대무역플랫폼 구축 사업 1단계 제안요청서.md`. 검증기 코드는 `Samples`로 적었지만 Windows에서는 같은 폴더다. 보고서에는 실제 확인한 표기를 쓴다.
- 설문지 샘플은 이미 기준선과 다르다(§4). §3.2의 사용자 결정 없이 기준선 값을 고치거나 원본을 복원하지 않는다. 사용자가 복원을 승인하면 `F:\38.AICowork\202609_HWPtoMD\samples\`의 파일이 SHA-256 `199c443b79e03fbe4c080cbd71addb0af559232607c8c03303f808bb974ea506`인지 확인한 뒤 복사하고, 기존 파일은 덮어쓰기 전에 백업 위치를 사용자에게 알린다.
- `BASELINE_CHANGED`는 기능 실패와 따로 집계한다. 파일이 없으면 다른 파일로 대신하지 말고 누락 경로를 적는다.
- 검증 전후 프로젝트 샘플의 SHA-256이 같아야 한다.

### 9.2 다중 탭 자료

`samples\`의 추가 문서(`2.AI기반 불공정거래 대응체계_제안요청서.md`, `KT DS_케이뱅크_GPU 플랫폼 구축_제안서_GPT_OpenShift AI_20260803.md`)는 탭 3~4개 시나리오와 메모리 측정(§6.8)에 읽기 전용으로 쓸 수 있다. 부속 폴더까지 임시 폴더에 복사해서 쓰고, 기준선 검사 대상에 넣으려면 사용자 확인을 받는다.

### 9.3 실제 Explorer 끌어다 놓기

- 자동 Qt 테스트와 별도로, 실제 Windows Explorer 창에서 파일을 편집기와 미리보기에 끌어다 놓아 확인한다. 여러 파일, 이미 열린 파일, 마크다운이 아닌 파일을 섞은 경우도 확인한다.
- 컴퓨터 조작 도구를 쓸 수 있으면 사용자 허락을 받아 직접 수행하고 스크린샷을 남긴다. 쓸 수 없으면 사용자에게 수동 확인 절차(준비할 파일 → 편집기에 놓기 → 미리보기에 놓기 → 여러 파일 → 결과 확인)를 주고, 결과를 받을 때까지 `NOT_CHECKED`로 둔다.
- 소스 실행과 설치본(§11) 모두에서 한 번씩 확인한다. 끌어다 놓은 원본 파일의 위치와 SHA-256이 그대로인지도 확인한다.

### 9.5 화면 확인

- 캡처: 두 문서 탭(각각 활성 상태), 편집기 글간격 100%와 150%, 다크 모드의 탭 화면, 문서가 없을 때의 안내 화면.
- 캡처를 실제로 열어 탭 제목, 활성 탭, 편집기, 미리보기, 글간격, 잘림 여부를 확인하고 소견을 보고서에 적는다. 캡처 파일이 있다는 이유만으로 통과시키지 않는다.
- 지금의 `--visual-confirmed`는 같은 실행에서 새로 만든 캡처에 `PASS`를 준다. 그래서 에이전트가 확인한 캡처와 보고서가 가리키는 캡처가 다를 수 있다. **[권장]** 이미 만든 보고서의 캡처를 확인한 뒤 그 보고서에 결과를 기록하는 방식(예: `--confirm-visual <report.json> --visual-note "…"`)을 검증기에 추가하고, 확인한 캡처의 경로와 SHA-256을 보고서에 남긴다. 고치지 않으면 확인한 캡처와 최종 보고서의 캡처가 같은지 직접 대조해 적는다.

### 9.6 보고서

기존 형식을 유지한다: `reports\verification_YYYYMMDD_HHMMSS.md`, 같은 이름의 `.json`, `reports\screenshots\`. 상태 어휘와 전체 판정도 기존과 같다: `FAIL`이 하나라도 있으면 `FAIL`, 그렇지 않고 `WARN`·`NOT_CHECKED`·`BASELINE_CHANGED`가 있으면 `WARN`, 모두 통과하면 `PASS`(해당 없음은 `NOT_APPLICABLE`).

## 10. 문서 갱신

구현과 실제 검증 결과에 맞춰 다음 한국어 문서를 고친다. 실제 UI와 다른 메뉴 이름이나 단축키를 쓰지 않는다.

- `README.md`: 7행 "한 번에 Markdown 문서 한 개 열기"와 154행 "다중 탭 … 지원하지 않습니다"는 이제 사실이 아니므로 고친다. 탭 열기·전환·닫기, 수정 표시 `*`와 저장 확인, 단축키(`Ctrl+W`, `Ctrl+Tab`, `Ctrl+Shift+Tab`), `보기 > 글간격 크게/작게`(편집기만, 80~150%), 끌어다 놓기(편집기·미리보기·탭 표시줄·안내 화면, 여러 파일, 이미 열린 파일), 명령줄과 `run_markdowneditor.bat`에 여러 파일 넘기기, 관리자 권한 실행 시 끌어다 놓기 제한, 최신 검증 보고서 경로와 실제 테스트 범위를 넣는다.
- `docs\사용설명서.md`: 12~13행 "한 번에 한 문서만 엽니다. 수정한 문서가 있으면 저장 여부를 먼저 묻습니다."를 새 동작으로 바꾼다. 글자 크기 절 옆에 글간격 절, 탭 사용 절차, 탭별 저장·닫기 대화상자, Explorer에서 끌어다 놓는 방법, 실제 검증 캡처를 넣는다.
- `docs\ARCHITECTURE.md`: 문서 세션과 탭 수명, 전역·탭별 상태 표(§6.2), 액션 라우팅, 비동기 렌더 격리, 외부 이미지 차단기 단일화, 끌어다 놓기 이벤트 경로.
- `docs\DECISIONS.md`: 메뉴 문구(PRD 그대로), 글간격 단계·범위, 줄 번호의 글간격 제외 여부, 툴바 배치 방식, 중복 경로 판정, 탭 닫기와 빈 상태, 드롭 구현(`NavigateOnDropEnabled`, `focusProxy()` 필터, `CopyAction`), 지연 생성, §3.2의 결정.
- `docs\PROGRESS.md`: 4차 마일스톤과 실제 테스트·검증 결과.
- `docs\Windows_배포_가이드.md`: 여러 파일 인자, 끌어다 놓기, 관리자 권한 주의 등 배포본 사용법이 바뀐 부분.
- `build\BUILD_REPORT.md`: 다시 빌드한 경우에만 새 크기·해시·검증 결과로 고친다.

## 11. Windows 배포 갱신

- 소스 검증을 마친 뒤 `scripts\build_windows.py`로 다시 만든다: `build\MarkdownEditor-Setup-<버전>-Windows-x64.exe`, `build\MarkdownEditor-<버전>-Windows-x64.zip`, 압축 해제 배포 폴더, `build\build_manifest.json`, `build\SHA256SUMS.txt`, `build\BUILD_REPORT.md`.
- 버전은 §3.2의 결정을 따른다. 올리면 `pyproject.toml`, `app.py`의 두 곳, 정보 대화상자를 함께 바꾸고, **[권장]** 한 곳(예: 패키지 `__version__` 또는 `importlib.metadata`)에서 읽게 한다. 유지하면 manifest와 `BUILD_REPORT.md`에 git 커밋 해시와 빌드 시각을 넣어 이전 빌드와 구분한다(이미 있으면 유지).
- 최근 커밋 `4dd4371`("Trim unused Qt components from the Windows bundle")이 새 기능에 필요한 것을 빼지 않았는지 번들을 실제로 실행해 확인한다.
- 배포 검증:
  1. 설치본과 휴대용 배포본에 새 모듈과 자산이 들어 있다.
  2. `build` 아래 격리된 테스트 경로에 설치한다.
  3. 설치된 실행 파일에 두 샘플 경로를 인자로 넘겨 탭 두 개로 동시에 연다.
  4. 글간격 메뉴와 문서 탭이 보인다.
  5. 한글·공백 경로의 마크다운으로 시작한다.
  6. 설치본에서 실제 Explorer 끌어다 놓기를 확인한다(§9.3).
  7. ZIP 전체 CRC를 검사한다.
  8. manifest, `SHA256SUMS.txt`, 실제 파일 SHA-256이 일치한다.
  9. 검증용 임시 설치·압축 해제 폴더는 정확한 경로를 확인한 뒤 지운다.
- 설치 EXE와 실행 파일이 코드 서명되지 않았으면 그 사실을 계속 적는다.

## 12. 실행·검증 명령

프로젝트 안의 uv 캐시와 Python 설치 폴더를 쓴다(`run_markdowneditor.bat`과 같은 방식, 실측).

```powershell
$env:UV_CACHE_DIR = "$PWD\.uv-cache"
$env:UV_PYTHON_INSTALL_DIR = "$PWD\.uv-python"

uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest -m "not gui"
uv run --locked pytest -m gui
uv run --locked python scripts\verify_samples.py
uv build
uv run --locked --no-sync python scripts\build_windows.py
```

- `tests\conftest.py`가 이미 `QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu`와 소프트웨어 OpenGL을 설정한다(실측). 보고서에 테스트 환경 설정으로 적는다.
- `--visual-confirmed`처럼 사람의 확인을 뜻하는 옵션은 캡처를 실제로 연 뒤에만 쓴다(§9.5).

## 14. 완료 조건

다음을 모두 실제 결과로 확인해야 4차 기능보완 완료로 보고한다.

1. `보기` 메뉴의 `글간격 크게`·`글간격 작게`가 단계·범위·저장 기준대로 동작하고, 글자 크기·테마 변경과 새 탭에서도 유지된다.
2. 여러 마크다운 파일이 각자의 편집기와 미리보기를 가진 탭으로 동시에 열린다.
3. 탭별 문서·렌더·스크롤·수정·저장 상태와 편집 메뉴·찾기·서식 명령의 대상이 섞이지 않는다.
4. 같은 파일을 다시 열면 기존 탭이 활성화되고, 저장이 다른 탭의 파일을 덮어쓰지 않는다.
5. 수정 탭 닫기와 여러 수정 탭이 있는 앱 종료에서 저장·버림·취소가 안전하게 동작한다.
6. 탭을 닫아도 남은 탭의 외부 이미지 차단이 유지된다.
7. 편집기와 실제 미리보기 영역(그리고 탭 표시줄·안내 화면)에 파일을 끌어다 놓아 열 수 있고, 본문에 URL 글자가 들어가지 않으며, 미리보기 셸이 바뀌지 않는다.
8. 여러 파일, 한글·공백 경로, 중복, 무효 항목 드롭이 §7.2대로 처리되고 항상 `CopyAction`으로 받는다.
9. 기존 단위·GUI 테스트와 새 테스트가 통과한다.
10. S24~S28이 통과하고, S29(실제 Explorer)는 증거와 함께 `PASS`이거나 사유와 함께 `NOT_CHECKED`다. 원본 샘플 SHA-256이 검증 전후 같다.
11. 라이트·다크, Mermaid 대비, Sync Scroll, 저장, 보안 등 기존 핵심 기능에 회귀가 없다.
12. 한국어 README, 사용설명서, 아키텍처, 결정 기록, 진행 문서, 배포 가이드가 실제 구현과 맞는다.
13. Windows 설치 EXE와 휴대용 ZIP을 다시 빌드하고 설치본 시작·CRC·SHA-256을 검증했다.

## 부록 B. v0.2(GPT) 검토 결과와 보완 내역

### B.1 바로잡은 사항

1. **자기 파일 경로**: v0.2 §1이 자신을 `…-v0.2-20260926.md`로 적었지만 실제 파일명은 `…-v0.2-GPT-20260926.md`다.
2. **메뉴 문구**: PRD가 정한 `글간격 크게`·`글간격 작게`를 v0.2가 `글자 간격`으로 바꿨다. 사용자가 직접 정한 이름이므로 PRD 문구로 되돌렸다(§2.2).
3. **원격 URL 드롭**: v0.2는 원격 URL을 "무효 항목 경고"로 묶어, 편집기에 웹 링크 글을 끌어다 놓는 기본 동작까지 막을 수 있었다. 로컬 파일이 들어 있는 드롭만 가로채고 나머지는 기본 동작을 유지하게 했다(§7.1–7.2).
4. **툴바 "전역으로 하나만"**: 지금 툴바는 편집기 위에 있고 단축키 액션을 스스로 만든다. 배치 유지와 "액션은 한 벌" 원칙을 함께 적었다(§6.3).
5. **드롭 수락 방식**: `acceptProposedAction()`을 쓸 여지가 있었다. 항상 `CopyAction`으로 받게 했다(§7.3).
6. **저장 충돌**: v0.2는 다른 이름으로 저장의 탭 간 충돌만 다뤘다. 날짜 저장(`Ctrl+S`)의 대상이 다른 탭에 열린 파일인 경우를 추가했다(§6.6).

### B.2 코드 실사로 새로 찾은 위험 (v0.2에 없음)

1. 미리보기마다 `NetworkGuard`를 공유 프로필에 설치하고 닫을 때 해제한다. 그대로 탭을 늘리면 탭 하나를 닫을 때 모든 탭의 외부 이미지 차단이 풀린다(§6.8).
2. 편집 메뉴, 자동 줄바꿈, 찾기·바꾸기 창이 첫 편집기에 고정되어 있다(§6.3).
3. 미리보기의 늦은 재시도가 수신 객체 없는 `QTimer.singleShot` lambda로 되어 있어 닫힌 탭에서 실행될 수 있다(§6.8).
4. `set_markdown_font_size()`가 글꼴을 새로 만들어 글간격을 지운다(§5.3).
5. `app.py`가 파일 인자를 하나만 받아 bat에 여러 파일을 넘기면 실행되지 않고, 종료 경로가 `window.preview` 하나만 정리한다(§4, §6.7).
6. 기존 드롭 테스트는 `MainWindow.dropEvent()`를 직접 불러 실제 자식 위젯 경로를 검증하지 않았다(§8.2-14).
7. `acceptNavigationRequest`는 링크 클릭만 막고 `NavigateOnDropEnabled`는 쓰지 않는다(§7.1).
8. 미리보기 제어 줄의 `Sync Scroll` 체크 상자가 탭마다 생기므로 값을 맞춰야 한다(§6.5).
9. 설문지 샘플이 이미 기준선과 다르고, 원본이 다른 프로젝트 폴더에 있다(§9.1).
10. README 7·154행과 사용설명서 12~13행이 새 기능과 모순된다(§10).
11. `--visual-confirmed`는 같은 실행에서 새로 만든 캡처에 `PASS`를 준다(§9.5).

### B.3 추가한 요구와 절차

- 전역·탭별 상태 소유 표, 탭 순서 이동 뒤 세션 식별, 드롭을 받는 안내 화면, 지연 생성과 메모리 측정, 같은 이름 파일의 탭 구분, 여러 파일 열기 결과 요약.
- 실제 Explorer 끌어다 놓기를 S29로 분리하고, 컴퓨터 조작 도구나 사용자 수동 확인으로 증거를 남기게 했다. 관리자 권한 실행 시 제한(UIPI)을 안내하게 했다.
- 사용자 결정 세 가지(기준선, 버전, git)와 답이 없을 때의 기본값(§3.2).
- 세션 분리를 다중 탭보다 먼저 하는 마일스톤, 요구사항 추적표, 실측 부록.
- `docs\Windows_배포_가이드.md` 갱신, 번들 축소 커밋 확인, 빌드 식별 정보(§10–11).
